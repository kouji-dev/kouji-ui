# SSR / Server Rendering Review

## Verdict

The *library* is in genuinely good SSR shape. Of 119 direct browser-global call sites across 54 non-spec files in `packages/core/src` + `packages/components/src`, **116 are guarded** — almost all via `afterNextRender` (53 files use it), `isPlatformBrowser`, or a `typeof document/window === 'undefined'` early return. The whole overlay stack (controller, stack service, mount/position/scroll-lock/focus-trap strategies) is explicitly platform-guarded, and the three heavyweight browser-only dependencies — ECharts, Monaco and Lexical — are all behind `await import(...)`, with `rich-text/index.ts` deliberately re-exporting only the Lexical-free surface. That is better than most Angular component libraries.

What drags the grade down is a small number of *load-bearing* exceptions plus the delivery layer. `KjLink` runs its screen-reader suffix injection through `inject(DOCUMENT)` inside an `effect()` rather than `afterNextRender`, so under SSR + hydration the span is appended on the server **and again** on the client. Verification narrowed that one: it does not reproduce anywhere in this repo (nothing here sets `target="_blank"` or `[kjExternal]`), causes no hydration error and fails no success criterion — it is a latent defect for downstream consumers, not a live production break. Three more `effect()` bodies touch the global `document` with no guard at all, two of which are the *unguarded copies* of a pattern that was correctly guarded in the two sibling files. On the app side, `apps/docs/src/server.ts` is dead code — `angular.json` has no `ssr.entry`, so nothing server-renders at runtime and the `/api/*` routes are never served anywhere; and every prerendered page ships behind a `z-index: 9999` splash **and** a `visibility: hidden` shell that only browser JS removes. That last one is narrower than first filed too: the content is still in the served HTML and in TransferState, so indexability survives — what is forfeited is the paint benefit, and the failure mode without JS is a stuck splash, not a blank page. It is also `apps/docs`-only; no published package is affected. For Analog/Vite specifically, `@kouji-ui/components` publishes its stylesheet tree at `src/**/*.css` with **no `exports` entries**, which the exports map generated by ng-packagr then makes unreachable to any resolver that honours `exports`.

**Grade: B−**

## What works

- **Overlay system is SSR-clean.** `KjOverlayController.runTransition` bails on `!this.isBrowser` (`packages/core/src/primitives/overlay/controller.ts:167`), `KjOverlayStack.register` returns a no-op handle on the server (`stack.ts:118-120`), `anchoredTo`'s `applyManual` guards first (`strategies/position/anchored-to.ts:125`), both scroll locks guard on `typeof document` (`strategies/scroll-lock/html-overflow.ts:8`, `strategies/scroll-lock/css-clip.ts:11`), and `getOverlayContainer()` returns `null` off-browser (`primitives/overlay/container.ts:27`). I specifically chased the `KjOverlayTrigger` effect at `primitives/overlay/trigger.ts:62-67` — which *does* call `controller.open()` on the server when a consumer binds `[kjOpen]="true"` — and every downstream strategy holds.
- **Heavy deps are all lazy.** ECharts: `await import('echarts')` inside `afterNextRender` (`chart/chart.ts:136-140`). Lexical: `const { createRichTextEngine } = await import('./engine')` (`rich-text/rich-text-editor.ts:224`), with `rich-text/index.ts` carrying an explicit comment that only Lexical-free symbols are re-exported — everything else is `import type`. Monaco: `import type { editor } from 'monaco-editor'` only (`editor/editor.types.ts:1`) plus a runtime `KjEditorLoader`. `marked` is a real runtime dep but is Node-safe.
- **Runtime-appended a11y nodes use `afterNextRender`, not effects.** `pagination/pagination.ts:218-229`, `pagination/pagination-ellipsis.ts:47-68`, `file-upload/file-upload.ts:398-408` and `file-upload/file-upload.ts:450-452` all wrap the injection in `afterNextRender` *and* re-check `typeof document`, so no server node exists and no duplication is possible. This is the correct pattern — `link.ts` is the one place that departs from it.
- **`KjId` exists and is the right design** (`primitives/overlay/id.ts:10-16`) — a root-provided, per-application-injector counter, which restarts per SSR request and therefore matches the client.
- **Direction/locale are honestly SSR-aware.** `provideKjDocumentDirection` returns before touching the DOM on the server (`locale/document-direction.ts:47`), and `KjLocale` is pure `Intl` + `LOCALE_ID` with no `navigator.language` sniffing (`locale/locale.ts:168-190`) — so no locale-driven text divergence between server and client.
- **Docs TransferState wiring is real and well thought out.** Split browser/server providers behind `DocsManifestProvider` / `RoadmapDataProvider` (`app.config.ts:36-37`, `app.config.server.ts:13-14`), a shared `makeStateKey` (`services/docs-manifest.provider.ts:14`), and an eager `provideAppInitializer(() => inject(RoadmapService))` with a comment explaining exactly why (`app.config.ts:38-45`). `getPrerenderParams` enumerates doc slugs from `DocsService` (`app.routes.server.ts:10-22`), and `theme-generator` is correctly opted out with `RenderMode.Client`.

## Findings

### F-1 `KjLink` injects its screen-reader suffix from an `effect()` instead of `afterNextRender`, so SSR + hydration emits it twice (latent for downstream consumers)

**Severity:** medium *(corrected during verification: filed as high; it does not reproduce anywhere in this repository and fails no WCAG success criterion)* · **Confidence:** high
**Files:** `packages/core/src/link/link.ts:22-23, 201-224`, `packages/core/src/link/link.spec.ts:147-171`, contrast `packages/core/src/pagination/pagination.ts:218`, `packages/core/src/file-upload/file-upload.ts:399`, `packages/core/src/pagination/pagination-ellipsis.ts:47`

**Evidence**

```ts
// packages/core/src/link/link.ts:201-219
    effect(() => {
      const external = this.isExternal();
      const doc = this.document;                     // inject(DOCUMENT) — works on the server
      if (!doc.createElement) return;
      const node = this.el.nativeElement;
      const consumerOwnsName = node.hasAttribute('aria-label');
      if (external && !consumerOwnsName) {
        if (!this.suffixSpan) {                      // ← instance state, not a DOM probe
          const span = doc.createElement('span');
          …
          node.appendChild(span);
          this.suffixSpan = span;
```

Effects flush during **server** change detection (unlike `afterNextRender`, which is browser-only), and platform-server's injected `DOCUMENT` has a working `createElement`, so the `if (!doc.createElement) return;` guard at `:204` is dead on the server and the span is serialized into the prerendered HTML. The directive's own comment about "prerender VMs" is an admission that the effect runs there. On hydration a fresh directive instance has `suffixSpan === null`, so it appends a **second** span and assistive tech reads "Documentation (opens in new tab) (opens in new tab)".

The same `suffixSpan === null` state disables the cleanup branch at `:220-223`: the server-rendered span can never be removed, so flipping `[kjExternal]` to `false` on the client leaves a stale suffix behind. One root cause, two symptoms.

This is the **only** place in the library that injects visually-hidden a11y DOM from an effect. The established pattern is `afterNextRender` plus a `typeof document === 'undefined'` guard — `pagination.ts:218`, `file-upload.ts:399`, `pagination-ellipsis.ts:47`. The SSR path is real: `apps/docs/src/app/app.config.ts` calls `provideClientHydration(withEventReplay(), withNoIncrementalHydration())` and `app.routes.server.ts` prerenders `**`.

**Impact assessment — latent, not live.** This does not reproduce anywhere in this repository. `kjLink` is used only by other library sources (`breadcrumb.ts`, `empty-state.ts`, `list.ts`, `components/link/link.ts`) and by no `apps/docs` template or example file; nothing in `apps/` or `packages/` sets `target="_blank"` or `[kjExternal]`, so the prerendered docs site emits **zero** suffix spans today. The defect bites downstream apps that hydrate an external `kjLink`. It causes no hydration error (unclaimed trailing siblings are ignored), no crash, and no keyboard or navigation loss — the accessible name stays correct, only redundant. No WCAG success criterion is actually failed; the cost is AT verbosity.

**Fix** Either move the injection to `afterNextRender` (matching its three siblings), or keep the effect reactive and make it idempotent by seeding `this.suffixSpan` from `node.querySelector('.kj-link-external-suffix')` on its first run so it **adopts** the server-rendered span instead of duplicating it — which also makes repeated `kjExternal` toggles idempotent.

> **Dropped from the evidence:** the claim that no CSS matches `.kj-link-external-suffix`. That is true but is not a defect — the span carries the complete visually-hidden rule as an inline `style` attribute (`link.ts:22-23`, applied at `:213`), and `link.spec.ts:157-160` asserts it. The class is a test/consumer hook by design, and the clause implied a second defect that does not exist.

**Coverage gap** There is no SSR/hydration test for any directive in the repo, so nothing would have caught this. The three suffix specs (`link.spec.ts:147, 162, 171`) are client-only.

**Effort:** S

### F-2 Docs site prerenders every page behind a splash that only browser JS removes

**Severity:** medium *(corrected during verification: filed as high; scoped to `apps/docs`, and the consequence was mis-stated)* · **Confidence:** high
**Files:** `apps/docs/src/app/services/loading.service.ts:9`, `apps/docs/src/app/app.ts:28, 44-46, 72, 82`, `angular.json:109`, `apps/docs/src/app/app.routes.server.ts`, `apps/docs/src/app/components/loading-screen/loading-screen.css`

**Evidence**

```ts
// apps/docs/src/app/services/loading.service.ts:9
  readonly isLoading = signal(true);
```
```html
<!-- apps/docs/src/app/app.ts:25-30 -->
@if (loading.isLoading()) { <kj-loading-screen /> }
<div class="app-shell" [class.content-hidden]="loading.isLoading()">
```
```css
/* apps/docs/src/app/app.ts:44-46 */
.content-hidden { visibility: hidden; }
```
```ts
// apps/docs/src/app/app.ts:71-83 — the only thing that clears it

  if (!this.isBrowser) return;                      // :72 — bails on the server
  this.appRef.isStable.pipe(…).subscribe(() => this.loading.hide());   // :82
}
```

With `"outputMode": "static"` (`angular.json:109`) and `**` prerendered (`app.routes.server.ts`, plus both `getPrerenderParams` slug tables), **every** prerendered file ships two blockers: the shell carrying `visibility: hidden`, **and** `<kj-loading-screen>` itself — the `@if` is not deferred, so the splash is prerendered too, and `loading-screen.css` renders it `position: fixed; inset: 0; background: var(--kj-bg-body); z-index: 9999`.

**Consequence, corrected.** The prerendered content **is** present in the HTML and in TransferState, so crawlers and text extractors still receive it — **indexability is not lost**. What is forfeited is the *paint* benefit: real-content FCP/LCP is gated on hydration plus the lazy route chunks settling, which is most of what prerendering is for. A no-JS or JS-failed client does **not** see a blank page — it sees a permanently stuck branded splash, with the content behind it occluded by the full-viewport overlay.

**Both blockers matter.** Dropping the `content-hidden` class alone is **insufficient** while the `z-index: 9999` splash still renders server-side — the overlay would occlude the content regardless.

**Fix** Seed `isLoading` to `false` on the server (or gate the splash on `isPlatformBrowser`) so prerendered output paints immediately and the splash becomes a browser-only overlay. Add an e2e to `playwright.static.config.ts` that fetches a prerendered route with JS disabled and asserts the `<h1>` is visible.

**Scope** `apps/docs` only. Nothing in `packages/*` — the published `@kouji-ui/*` that consumers install — is affected, so no downstream app inherits this. It is a self-inflicted LCP regression on one internal docs site.

**Effort:** S

### F-3 `KjChart` calls global `document.createElement` inside an `effect()`

**Severity:** medium · **Confidence:** high
**Files:** `packages/core/src/chart/chart.ts`

```ts
// packages/core/src/chart/chart.ts:232-242
    effect(() => {
      const text = this.kjChartDescription();
      const id = this.descriptionId();
      const host = this.el.nativeElement;
      if (!text) {
        descDiv?.remove();
        descDiv = null;
        return;
      }
      if (!descDiv) {
        descDiv = document.createElement('div');
```

**Why it matters.** Unlike the ECharts init block right above it (`chart.ts:136`, correctly inside `afterNextRender` with a `try/catch` whose comment reads "ECharts cannot initialize in non-browser environments (jsdom, SSR)"), this is a plain `effect()` reading the **global** `document`, which `@angular/platform-server` does not define. The `if (!text) … return` at line 236 is the only thing standing between a server render and `ReferenceError: document is not defined` — so the crash fires exactly when a consumer sets `kjChartDescription`, which is the documented long-description input for a `role="img"` chart (`chart.ts:83-84`, host `role: 'img'` + `[attr.aria-describedby]` at `chart.ts:65-69`) and therefore the *recommended* a11y configuration. Angular routes effect errors through `ErrorHandler` rather than aborting the render, so the practical symptom is a noisy prerender log and a missing `aria-describedby` target rather than a hard build failure — but it is a real unguarded, server-reachable DOM access in the most-used a11y path of the component.

**Fix.** Same treatment as the sibling block: `inject(DOCUMENT)` and guard, or move the description-div maintenance behind `afterNextRender` with a reactive re-sync. If it is allowed to run on the server it must also be made idempotent (see F-1), otherwise it acquires F-1's duplication bug.
**Effort:** S

### F-8 There is no Vite / Analog installation path documented or tested

**Severity:** medium · **Confidence:** high
**Files:** `apps/docs/src/app/pages/getting-started/getting-started.ts`, `packages/themes/package.json`, `package.json`

**Why it matters.** Getting Started's only styling instruction is an `angular.json` `styles[]` array (`getting-started.ts:26-32`). A consumer on Analog has no `angular.json`; they need module imports. Concretely, under Analog:

- **The CSS imports must be reachable via `exports`.** Core: yes (`packages/core/package.json:52-69`). Themes: yes (`packages/themes/package.json:32-37`, `"." → ./src/index.css`). Components: **no** — F-6, so every themed overlay surface paints unstyled.
- **`@kouji-ui/themes` has no `"./package.json"` export** (`packages/themes/package.json:32-37`), so any tool that resolves `@kouji-ui/themes/package.json` — a common dependency-scanning move — hits `ERR_PACKAGE_PATH_NOT_EXPORTED`.
- **CSS from a server bundle.** Vite's SSR pipeline handles `.css` specifiers (collected, not executed), so `import '@kouji-ui/themes'` from a component is safe server-side. A *bare Node* `import('@kouji-ui/themes')` resolves to a `.css` file and throws `ERR_UNKNOWN_FILE_EXTENSION` — worth knowing, but no realistic setup does that.
- **The FESM / externalization side looks fine.** Both libraries are `"sideEffects": false` with pure-ESM FESM2022 output, no CommonJS interop, and — per the guard audit above — no top-level browser-global access anywhere in the module graph, so Vite can externalize them for SSR without `ssr.noExternal`.

So the only hard Analog blocker I can identify is F-6 — but nothing in the repo would catch a regression, because there is no Vite/Analog smoke target at all, despite `@analogjs/vite-plugin-angular` already being a devDependency (`package.json:61`, used only for Vitest).

**Fix.** Add a minimal Analog/Vite smoke target, or a CI script that `npm pack`s all three tarballs, installs them into a scratch Vite+Angular app, and asserts the bare entry and each documented CSS subpath resolve. Add a "Vite / Analog" tab to Getting Started next to the `angular.json` snippet.
**Effort:** M

- **F-13** Virtualized tables render zero rows into the prerendered HTML — a correct `afterNextRender` guard with an undocumented indexability trade-off.
- **F-14** SSR safety rests on `typeof document === 'undefined'` rather than `isPlatformBrowser`, which is environmental rather than architectural: any host that shims a DOM onto `globalThis` turns `container.ts`'s `_root`, the scroll-lock refcounts and `_announce.ts`'s `regions` into process-global state shared across concurrent requests.
- **F-9** — the prior pass listed module-level id counters only as an MFE concern (`05-micro-frontends.md` F-1); this pass adds the SSR-specific angle: in a single prerender process rendering the whole route table, the counters keep climbing, so a page prerendered late carries `id="kj-field-137"` while the hydrating client mints `kj-field-1`.
